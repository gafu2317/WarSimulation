# 自動戦闘デバッグ

| 用途 | 実行口 | 設定形式 |
|---|---|---|
| 単一編成の連戦 | `-autoBattleConfig` | `Allies` / `Enemies` / `MatchCount` |
| 複数候補の探索 | `-autoBattleSweepConfig` | `Candidates` / `Enemy` / `MatchesPerCandidate` |
| 分割・並列・再開 | `batch_battles.py` | Sweep設定＋`Batch` |

マップ候補・味方編成・敵編成・試合回数を指定し、Standalone Player を CLI から起動して連戦する。
編成探索（Sweep）では、制約付きの武器×性格候補を複数生成し、既定では固定 Neutral 敵との勝率ランキングを出す（`Enemy` 指定時はその編成を使う）。

Editor Play は使わない。低 FPS になるため。

主目的は、各試合の[診断ログ](診断ログ.md)を残してあとから AI 判断を追えるようにすること。編成探索では勝率 JSON も残す。

性格の事前検証では、勝敗や `Outcome` を合否条件にしない。対象性格について、診断ログの `AI_PLAN` で `PersonalityPreference` または `PersonalitySignature` が発火し、`AI_EXECUTE` で移動・技能の開始可否と失敗理由を確認する。仕草が必要な性格は「発火機会 → 計画選択 → 行動開始 → 完了」が観測できることを先に判定し、勝率はその後の編成比較で使う。

## 準備

1. 戦闘シーン（例: `Assets/Scenes/GafuTest.unity`）を開く
2. `CombatAutoBattleRunner` があること（無ければ空の GameObject に追加。実行時に `CombatBattleEventLogger` も追加される）
3. Inspector で次を設定する
   - **マップ候補**（`AuthoredMapDefinition`。空だと起動直後に失敗する）
   - **Weapon Configs**（推奨。未設定時のみ `CombatCharacterSelection` の Weapon Options にフォールバック）
   - 味方/敵プールが探索最大人数（既定 6）以上あること
   - 単一連戦用の味方編成 / 敵編成・試合数・基準シード・タイムアウト・時間倍率
4. シーンを保存する
5. Build Target を StandaloneOSX にする
6. `Tools/War Simulation/Auto Battle/Build Player` でビルドする（Development Build）

ビルド出力: `.unity/CombatAutoBattle/CombatAutoBattle.app`

## 連戦まわりの仕様（現行）

- 試合シードは `StartBattleOnCurrentMap(seed)` に渡し、`CombatBattleRandom` と `UnityEngine.Random` を揃える
- タイムアウト時は `AbortBattle()` でスキル一時物・キャラ/魔石をリセットしてから次試合へ
- 同じマップ定義の連続試合では `ApplyAuthoredMap` をスキップし、参加者再設定＋再配置だけ行う
- 性格プロファイルは Kind 単位でキャッシュ再利用する
- レポートの `Outcome` は `Victory` / `Defeat` / `Timeout`
- 試合（または候補）完了ごとにレポート JSON を上書き保存する
- タイムアウト時は診断ログを先に閉じてから `AbortBattle()` する（終了時点の HP/魔石を残す）

## 単一編成の設定 JSON

```json
{
  "MapNames": ["AuthoredMap 1"],
  "Allies": [
    { "Weapon": 1, "Personality": 0 },
    { "Weapon": 3, "Personality": 19 }
  ],
  "Enemies": [
    { "Weapon": 1, "Personality": 0 },
    { "Weapon": 1, "Personality": 1 }
  ],
  "MatchCount": 10,
  "BaseSeed": 12000,
  "TimeoutSeconds": 600,
  "TimeScale": 6
}
```

同じ`BaseSeed`を全試合で繰り返す場合は`"FixedSeed": true`、倍速時も物理刻みを維持する場合は`"PreserveFixedDeltaTime": true`を加える。

- `MapNames` はシーン上 Runner に割り当て済みのマップ名。省略時は Inspector の候補を使う
- `Weapon` / `Personality` は enum の整数値（JsonUtility）
- 編成・試合数などを省略した項目は、ビルド時の Inspector 値を使う

`WeaponKind`: Unarmed=0, Sword=1, Shield=2, Wand=3, Grimoire=4, Bible=5, Rosary=6  
`CombatAiPersonalityKind`: Neutral=0, AttentionSeeker=1, BattleJunkie=2, Cunning=7, Devoted=9, Lonely=16, Reckless=19, Gatekeeper=20, Tagalong=21, Avenger=22, HighGround=24, StandoffSiege=25

## 編成探索（Sweep）

敵は既定で Neutral 5 人（Sword×2, Shield, Wand, Rosary）。味方候補は次の制約で生成する。

- 人数 4〜6
- `Sword + Wand ≥ 2`
- `Shield ≤ 2` / `Bible ≤ 2` / `Grimoire ≤ 2`（各武器種）
- 自動生成の性格は現在の affinity 表（剣・杖: 戦闘狂／狡猾／猪突猛進、盾: 陽キャ／献身的／寂しがり、その他: 献身的／寂しがり）から選び、標準（Neutral）はサンプリングに入れない。門番・便乗屋・復讐鬼・高所好きは `Candidates` で明示した場合にだけ評価する
- 既定の連携シード編成を候補に混ぜる

サンプル: `Tools/AutoBattle/sample-sweep.json`

```json
{
  "MapNames": ["AuthoredMap 1"],
  "CandidateCount": 40,
  "MatchesPerCandidate": 8,
  "BaseSeed": 12000,
  "MinPartySize": 4,
  "MaxPartySize": 6,
  "TimeoutSeconds": 600,
  "TimeScale": 6
}
```

明示候補を置く場合は `Candidates` 配列（人数が範囲外のものはスキップ）。明示候補は適性チェックをしない。

## CLI（短時間の確認用）

以下のCLI例は短時間の確認用であり、Codexセッション終了後の継続は保証しない。長時間の連戦・編成探索は、[汎用自動戦闘バッチ](汎用自動戦闘バッチ.md)の`Terminal.app`＋`caffeinate`手順で起動する。

単一編成:

```bash
./.unity/CombatAutoBattle/CombatAutoBattle.app/Contents/MacOS/CombatAutoBattle \
  -screen-fullscreen 0 \
  -screen-width 1280 \
  -screen-height 720 \
  -logFile Logs/AutoBattles/player.log \
  -autoBattleConfig /absolute/path/to/run.json
```

編成探索:

```bash
./.unity/CombatAutoBattle/CombatAutoBattle.app/Contents/MacOS/CombatAutoBattle \
  -screen-fullscreen 0 \
  -screen-width 1280 \
  -screen-height 720 \
  -logFile Logs/AutoBattles/player.log \
  -autoBattleSweepConfig /absolute/path/to/sweep.json
```

Editor メニュー:

- `Tools/War Simulation/Auto Battle/Build And Run With Config...`
- `Tools/War Simulation/Auto Battle/Build And Run Sweep...`

## 結果

### 診断ログ（本体）

各試合 1 ファイル:

```text
Logs/CombatBattles/battle_yyyyMMdd_HHmmss_fff.log
```

内容・読み方は[診断ログ](診断ログ.md)と同じ。時間切れは `BATTLE_END outcome=Timeout`。

### 単一連戦レポート

`Logs/AutoBattles/<timestamp>.json`

`Outcome` は `Victory` / `Defeat` / `Timeout`。`DiagnosticLogPath` で診断ログを指す。

### 編成探索レポート

`Logs/AutoBattles/sweep_<timestamp>.json`

候補ごとの Roles・Wins/Losses/Timeouts・WinRate。候補完了ごとに上書きし、最終的に WinRate 降順。
