# 汎用自動戦闘バッチ

編成、敵編成、マップ、シード、試合数、timeout、倍速をJSONで指定し、軽量Standalone Playerを複数起動して戦闘を行う。

システム側に編成人数、使用マップ、並列数、倍速の固定値はない。`Tools/AutoBattle/batch-example.json`の値は実行例であり、要件ではない。

## 設定

戦闘設定は`CombatCompositionSweepConfig`と同じ形式を使う。

| キー | 内容 |
|---|---|
| `MapNames` | Runnerに登録済みのマップから使用する名前 |
| `Candidates` | 評価する味方編成。省略して`EnumerateAllCandidates`も使用可能 |
| `Enemy` | 対戦する敵編成 |
| `MatchesPerCandidate` | 各候補・各マップで行う総試合数 |
| `BaseSeed` | 基準シード |
| `TimeoutSeconds` | 1試合のゲーム内timeout |
| `TimeScale` | 戦闘の倍速 |
| `EvaluateBothStonePositions` | 通常配置と反転配置を両方評価するか |
| `UseCommonSeeds` | 候補間で同じシードを使うか |
| `DisableDiagnostics` | 大量実行時の詳細診断ログを止めるか |
| `PreserveFixedDeltaTime` | 倍速時も物理刻みを維持するか。`true`は比較の安定性を優先し、`false`は速度を優先する |

`Setup Current Scene`は`Assets/Data/Map/Map/Authored`にある利用可能なマップをRunnerへ登録する。選択したマップが、通常・反転のうち実行対象にした配置を開始できる必要がある。編成人数はシーンが持つ味方・敵キャラクタープール数まで指定できる。

設定を省略した場合の既定値は、`TimeScale=6`、`ParallelProcesses=5`、`JobWorkerCount`はPlayer既定値である。比較実験では、再現性のためこれらを設定JSONに明示する。

`Batch`は外部ランチャーだけが読む。

| キー | 内容 |
|---|---|
| `MapExecution` | `each`は各マップを個別評価、`seeded`はシードで候補マップを選択 |
| `MatchesPerJob` | 中断・再開単位となる1ジョブの試合数 |
| `ParallelProcesses` | 同時に起動するPlayer数 |
| `JobWorkerCount` | 各Unity PlayerのJob Worker数。省略可能 |
| `Executable` | 軽量Playerまたは実行ファイルのパス |
| `OutputRoot` | 新規実行結果の親ディレクトリ |

## 実行

戦闘シーンを開き、Play Modeを停止した状態で次を実行する。

1. `Tools > War Simulation > Auto Battle > Setup And Build Lightweight Player`

その後、プロジェクトルートで実行する。

初回とPlayer再ビルド後は、同じ設定を1試合へ縮小するスモーク実行で終了コードとレポートを確認する。

```bash
python3 Tools/AutoBattle/batch_battles.py \
  --config Tools/AutoBattle/batch-example.json \
  --smoke
```

```bash
python3 Tools/AutoBattle/batch_battles.py \
  --config Tools/AutoBattle/batch-example.json
```

並列数と倍速は設定を編集せず上書きできる。

```bash
python3 Tools/AutoBattle/batch_battles.py \
  --config Tools/AutoBattle/batch-example.json \
  --parallel 4 \
  --time-scale 16
```

`--matches-per-job`と`--job-worker-count`も同様に上書きできる。

## 中断と再開

初回実行で表示された出力ディレクトリを指定して再実行する。

```bash
python3 Tools/AutoBattle/batch_battles.py \
  --config Tools/AutoBattle/batch-example.json \
  --output-directory Logs/AutoBattleBatch/<run>
```

設定のfingerprintが一致する場合だけ再開し、`complete.json`があるジョブはPlayerを起動せず再利用する。失敗・中断したジョブは新しい`attempt_*`ディレクトリで再実行するため、以前のログを失わない。

ランチャーをCtrl+Cで停止すると、管理中のPlayerへ終了要求を送り、完了マーカーがないジョブを次回の再実行対象にする。

設定内容が異なる出力ディレクトリは再利用できない。並列数とUnity Job Worker数は戦闘内容ではなく実行方法なので、再開時に変更できる。

## モデルベース編成探索

`adaptive_search.py` は、5人編成の全6,993候補を戦闘なしで列挙し、次の段階だけUnity Playerで評価する。

```text
共通300候補 × 1試合
  → シナリオごとに役割・役割ペアを学習
  → 予測Top 60 + 情報不足20 + 近傍20を各3試合
  → 各シナリオの上位10候補を各20試合
```

10マップを指定すると、既定では通常配置と反転配置を別シナリオとして実行する。敵編成は杖・標準×2、聖書・献身的、ロザリオ・献身的、魔導書・戦闘狂で固定される。`AdaptiveSearch` の `PartySize`、`InitialCandidates`、`ProbeMatches`、`FinalMatches` などで探索規模を変更できる。通常配置・反転配置は同一候補でも別々のモデルを持つ。

```bash
python3 Tools/AutoBattle/adaptive_search.py \
  --config Tools/AutoBattle/adaptive-search-example.json
```

出力先を指定しておけば、外出中に停止しても同じコマンドで再開できる。完了済みジョブはPlayerを再起動せず、`final-results.json`、`models.json`、`selection.json` と `stages/` に結果を残す。

## 結果

`summary.json`に次を保存する。

- 完了・今回実行・再利用・失敗ジョブ
- 総試合数と試合/分
- 候補ごとの勝利、敗北、timeout、勝率
- ゲーム内時間の平均・中央値・最小・最大・決着戦中央値と、実時間の合計・平均
- AI判断スキップ数
- マップ、魔石配置別の同じ統計
- TimeScale、固定刻み、PlayerビルドGUID、Unityバージョン

各ジョブの設定、Playerログ、元のsweepレポートは`jobs/<job>/attempt_*`に残る。

## 精度上の注意

このバッチは既存Unity戦闘を実行する。`TimeScale`、`PreserveFixedDeltaTime`、並列負荷を変えると、NavMeshとフレーム駆動AIの結果が変わる可能性がある。比較実験ではこれらを同一にし、速度設定を変えた実行結果を同じ母集団として結合しない。
