# 進攻ルートオーサリング設計

関連: [README](README.md) · [進攻ルート](進攻ルート.md) · [進攻ルートとソフト分散](進攻ルートとソフト分散.md)

実装済み。旧ベイクフィールドだけは既存アセット移行のため非表示で保持する。

## Contract

### Outcome

マップ編集中に進攻ルートを確認・自動生成・手動編集でき、検証済みルートが `MapData` の一部として戦闘AIまで同じ形で届く。

### Acceptance Criteria

1. マップエディタの2Dプレビューに、編集中とNavMesh検証済みの進攻ルートが区別して表示される。
2. 既存のNavMeshルート列挙を使って自動候補を作れる。
3. 経由点の追加・移動・削除と、ルートの追加・削除がUndo対応できる。
4. ルートの正本は `AuthoredMapDefinition`、検証済み実行時データは `MapData.AssaultRoutes` となる。
5. 地形変更とルート変更の古さを別々に判定し、ルート編集だけでNavMesh再ベイクを必須にしない。
6. 戦闘開始時は検証済みルートのみをAIが利用する。

### Interpretation

- プロジェク内の既存用語に合わせ、「侵攻ルート」ではなく「進攻ルート」と表記する。
- 現在の `MainStonesPerSide = 1` を対象とする。複数の主魔石間のルート組み合わせは今回のデータ形式に入れない。
- ルートは自軍主魔石から敵軍主魔石への正方向で1本だけ保持し、敵軍は逆順で使う。

## 現状と変更理由

現在も `AuthoredMapNavBake` がNavMeshベイク後に `CombatStoneAssaultRoutes.BuildCandidates` を呼び、`AuthoredMapDefinition` へ自軍用・敵軍用の `AuthoredBakedAssaultRoute` を保存している。ただし、次の点がマップオーサリングとして足りない。

- ルートが `MapData` の外にあり、マップとルートの参照経路が分かれている。
- ベイク結果は橋の入口・出口だけで、手動編集できる正本がない。
- 2Dプレビューは地形と配置物だけを描画し、ルートを表示しない。
- `BridgeFeatureIndex` をAIのルート識別子にしているため、橋を使わない手動ルートを表せない。
- 地形とルートが同じ fingerprint に結びついており、ルートだけの変更でもNavMeshを再ベイクする構造になる。

## 採用するデータモデル

### 編集用の正本

`AuthoredMapDefinition` に `List<AuthoredAssaultRoute> AssaultRoutes` を追加する。

```text
AuthoredAssaultRoute
  RouteId: string
  DisplayName: string
  Source: Auto | Manual
  Waypoints: List<Vector2>  // マップローカルXZ、中間経由点のみ
```

- 始点と終点は自軍・敵軍の主魔石から求め、`Waypoints` に重複保存しない。
- `RouteId` は作成時に発行し、表示名や並び順を変えても維持する。AIのソフト分散もこれをルートキーに使う。
- 自動生成ルートの点を1つでも手動変更したら `Source = Manual` にする。これにより次回の自動生成で意図せず上書きしない。

### 実行時データ

`MapData` に `List<AssaultRoute> AssaultRoutes` を追加する。

```text
AssaultRoute
  RouteId: string
  DisplayName: string
  Corners: IReadOnlyList<Vector3>  // マップローカル、始点・終点を含むNavMesh検証済み経路
```

- `Corners` は編集対象ではない。`AuthoredAssaultRoute.Waypoints` の各区間をNavMeshで計算し、連結したベイク結果とする。
- `BakedMapData` は `AssaultRoute` をシリアライズし、`CreateRuntimeMap()` で `MapData.AssaultRoutes` へ復元する。
- `CombatAssaultRouteCache` はルート生成器ではなく、`MapData.AssaultRoutes` をマップ原点に合わせてワールド座標化する薄いキャッシュにする。
- 既存の `BridgeFeatureIndex` / `HasBridgeWaypoints` / `Enter` / `Exit` は、汎用の `RouteId` / `Corners` に置き換える。

## 編集状態と検証状態

編集中の経由点とNavMesh上の実経路を同じデータにしない。

```text
Authored waypoints (常に保存・Undo対象)
  -> NavMesh検証
  -> Baked corners (MapDataに保存・AIが使用)
```

状態は次の3つとする。

| 状態 | 2Dプレビュー | 戦闘利用 |
|---|---|---|
| 検証済み | 太い実線で `Corners` を表示 | 可 |
| 未検証 | 経由点ハンドルのみ表示 | 不可 |
| 検証エラー | 通らない区間を赤で表示 | 不可 |

地形を動かしても編集中ルートは消さず、古い検証済み経路を現行マップの有効ルートとして表示しない。3D反映後は保持したルートを現行NavMeshで自動再検証する。

## fingerprint の分離

`ComputeBakeFingerprint()` を用途別に分ける。

```text
GeometryFingerprint
  = 現在の ComputeBakeFingerprint 相当

AssaultRouteFingerprint
  = GeometryFingerprint + AuthoredAssaultRoutes
```

- `BakedMapData` の地形、NavMesh、3D表示は `GeometryFingerprint` で鮮度判定する。
- 検証済み進攻ルートは `AssaultRouteFingerprint` で鮮度判定する。
- プレビューPNGにルートを焼き込む場合は `AssaultRouteFingerprint` を使う。
- `BakedMapData` は地形キャプチャとルートキャプチャの更新を分ける。ルートだけを修正した場合、既存NavMeshが現行ならそれを再利用する。

## マップエディタUI

### ツール

上部ツールバーに「進攻ルート」を追加する。右パネルには次を表示する。

- ルート一覧、表示名、生成元、検証状態
- 「手動ルートを追加」
- 「自動ルートを更新」
- 自動再検証と、失敗時に使う「全ルートを今すぐ再検証」
- 選択中ルートの経由点一覧と削除

### キャンバス操作

- 空き地点のクリック: 選択ルートの経由点を末尾に追加
- 経由点のドラッグ: 移動
- 線分のクリック: その位置に経由点を挿入
- Delete / Backspace: 選択経由点を削除
- ルートの削除は右パネルの明示ボタンで行う

自軍主魔石と敵軍主魔石は暗黙の端点とし、ルート編集中には動かさない。魔石自体の移動は既存の魔石ツールで行う。

### 表示

- 自軍から敵軍方向へ矢印を付ける。
- ルートごとに色を分け、選択中のルートだけ経由点ハンドルを出す。
- 経路線は検証済みcornersだけを表示し、waypoints間の単純な直線は表示しない。
- 保存するマッププレビューPNGには検証済みルートのみを方向なしの線で描画する。これにより魔石位置反転表示でも破綻しない。

## 自動生成

自動生成は別の2D経路探索を新設せず、既存の `CombatStoneAssaultRoutes.BuildCandidates` を使う。プレビューと戦闘で通行可否が一致することを優先する。

1. `GeometryFingerprint` が一致するベイク済みNavMeshを用意する。古い場合は「シーンへ3D反映」を促し、古いNavMeshで生成しない。
2. 自軍主魔石から敵軍主魔石への候補を `BuildCandidates` で列挙する。
3. 直進候補は中間経由点0個、橋候補は岸側の入口・出口を中間経由点として `AuthoredAssaultRoute` に変換する。
4. `Source = Auto` のルートだけを置換し、`Manual` は保存する。
5. 候補を検証し、成功した経路を `MapData.AssaultRoutes` にキャプチャする。

自動生成は明示ボタンのみで実行する。地形のドラッグ中やプレビュー再構築ごとにNavMesh計算しない。

## 手動ルートのNavMesh検証

1. 主魔石と全経由点を、現行の進攻ルートと同じエリアマスクでNavMesh上へサンプルする。
2. 隣り合う点ごとに `NavMesh.CalculatePath` を行う。
3. 全区間が `PathComplete` のときだけ corners を連結する。
4. 重複する区間端点は1点にまとめる。
5. 1区間でも失敗したらルート全体を無効とし、失敗区間をエディタで示す。部分的なルートはAIへ渡さない。

`River` と非凍結 `Lake` を除外するエリアマスクは既存の仕様を維持する。サンプル半径などの数値も既存仕様から共通化し、エディタ専用の別値は追加しない。

## AIの利用

AIは `Corners` の入口・出口だけでなく、ルート全体から次の目的地を求める。

1. キャラクター位置をルート線分上へ投影し、正方向の進捗度を得る。
2. 進捗度より先にある次の corner を移動候補にする。
3. 敵軍は corners を逆順に見る。魔石位置反転時は現在と同じくチームの参照方向を入れ替える。
4. ソフト分散は `RouteId` ごとに混雑を数える。

進捗度から次点を求めるため、橋を通過したキャラクターを古い入口へ戻す分岐は不要になる。ルートの固定担当は今までどおり追加しない。

## 保存と戦闘開始条件

- `AuthoredMapValidator` はルートIDの空・重複、経由点のマップ外、主魔石不足を静的に検査する。
- NavMesh上の到達可否はベイク時の動的検証で行う。
- ルートが1本もない、または全ルートが無効なマップは戦闘開始不可とする。
- `CombatMapAvailability` は `MissingAssaultRoutes` と `StaleAssaultRoutes` を維持し、判定先を `BakedMapData` 内のルートデータへ変える。
- 自動生成で候補0本になった場合、既存ルートは削除せずエラーを表示する。

## 変更フロー

```text
地形・橋・魔石を編集
  -> 2Dプレビュー再構築
  -> 古い検証済み線を非表示
  -> シーンへ3D反映（Geometry/NavMesh更新）
  -> 既存ルートを自動再検証、または自動ルート更新
  -> MapData.AssaultRoutes へキャプチャ
  -> 2Dプレビューに検証済み実線
  -> プレビューPNG保存
```

## 移行

1. 既存の `_bakedAllyAssaultRoutes` のうち、橋ルートは `EnterLocal` / `ExitLocal` を `AuthoredAssaultRoute.Waypoints` へ移し、直進は経由点0個とする。
2. 移行後に現行NavMeshで全ルートを再検証する。
3. `_bakedEnemyAssaultRoutes` は正方向の逆順であるため移行元に使わない。
4. 新データが有効なことを確認してから旧フィールドを削除する。

## 実装順序と検証

### Phase 1: データと移行

- `AuthoredAssaultRoute` / `AssaultRoute` を追加する。
- `MapData` / `BakedMapData` / fingerprint / availability を変更する。
- 旧ベイク済みルートからの移行を行う。

証拠: `BakedMapData` 往復で `RouteId` と全 corners が保持され、ルート編集でNavMeshの鮮度が落ちないテスト。

### Phase 2: 生成とNavMesh検証

- 既存の自動列挙をオーサリングデータへ変換する。
- 手動経由点列から検証済み corners を作る。

証拠: 直進、1橋、複数橋、到達不可区間に対するEditorテスト。

### Phase 3: マップエディタ

- 動的オーバーレイ、ルート一覧、手動操作、自動更新、Undoを追加する。
- 保存プレビューPNGに検証済みルートを描画する。

証拠: 追加・挿入・移動・削除・Undoの各操作と、状態別表示の手動確認。

### Phase 4: AI切り替え

- `CombatAssaultRouteCache` と移動候補を `MapData.AssaultRoutes` / `RouteId` / corners進捗度へ切り替える。
- ランタイム自動再構築を削除し、旧フィールドは移行期間中だけ非表示で保持する。

証拠: 自軍・敵軍・魔石位置反転で次点が正しく逆転し、複数ルートのソフト分散が `RouteId` 単位で働くテスト。

## 対象外

- 複数の主魔石ペアを結ぶルート定義
- キャラクターごとのルート固定割当
- 対岸射撃点のオーサリング
- ランタイムの動的な再ルートベイク
- NavMeshと異なる2D専用経路探索
