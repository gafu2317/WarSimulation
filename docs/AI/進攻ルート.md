# AI進攻ルート設計

関連: [README](README.md) · [移動](移動.md) · 実装 [`CombatStoneAssaultRoutes.cs`](../../Assets/Scripts/Combat/Debug/CombatStoneAssaultRoutes.cs)

## この段階の責務

マップから進攻ルート候補を作ること。AI 側は `CombatAssaultRouteCache` 経由で同じ列挙を文脈に載せ、移動採点で使う（詳細は [進攻ルートとソフト分散](進攻ルートとソフト分散.md)）。

デバッグ表示（`CombatStoneAssaultRouteDebugView`）も同じ `BuildCandidates` を参照する。

## いま実装していること（薄い版）

1. スタート = 自軍メイン魔石、ゴール = 敵軍メイン魔石
2. まず直進 `start → goal` を試す
3. 直進が通って **どの橋にも触れない** → 直進1本だけ（川なし／同じ岸）
4. 直進が橋を使う、または直進不可 → 各橋で `開始 → 岸A → 岸B → ゴール` を列挙
5. River/Lake area は areaMask から除外（高コストではなく不通）

対岸射程・幾何的な重複除去は後段。

## 計算タイミング

**Play 中**、マップ＋NavMesh 準備直後（`CombatMapSystem` が最終 `SetCurrentMap` したあと）に `CombatAssaultRouteCache.EnsureBuilt` で一度構築する。
AuthoredMap に Editor ベイク済みルートがあれば hydrate、無ければ `BuildCandidates` で列挙する。
AI Collect 側の `EnsureBuilt` はフォールバック（NavMesh Sample 未準備時の再試行）。デバッグ表示も Play 開始後に描画する。

マップ編集後は MapAuthoring の「シーンへ3D反映」で 3D 描画とともに `NavMeshData` とルート POD を AuthoredMap に保存する。

## 注意

NavMesh の「高コスト」は歩ける。長い川渡りを防ぎたいならコスト任せではなく、River 除外＋水面棄却が必要。
