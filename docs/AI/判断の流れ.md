# 判断の流れ

関連: [README](README.md) · [目的と戦況](目的と戦況.md) · [移動](移動.md) · [スキルと対象](スキルと対象.md) · [性格](性格.md)

主な実装: `CombatCharacterSystem.TickAiDecisionsNow`, `CombatAiBrain`, `CombatAiPlanner`

## チーム一括の Prepare → Execute

既定の判断間隔は `CombatCharacterSystem` の AI 間隔（既定 0.5 秒）。

1 回の tick:

1. 視界スキャンと味方間の視界共有
2. 陣営ごとのチーム予約をクリア
3. 全 Brain を順に Prepare（成功した計画を予約へ登録）
4. 全 Brain を順に Execute

後続キャラは、先行キャラの計画・予測ダメ／回復を文脈に含められる。

## 1 キャラの Prepare

- AI 無効・行動不能・詠唱中は計画を作らない
- 文脈収集
- `BuildPlan`: 戦況 → `SelectState` → `BuildPlanForState`
- 寂しがりが単独のときは `Search` を選び、味方探索移動だけを行う

詠唱中は新しい判断を行わず、開始済みスキルの完了を待つ。

「スキル」には通常攻撃を含む。

## BuildPlan

1. 文脈から戦況指標を作る
2. 安価な条件を優先順に確認し、六ステートから一つを選ぶ
3. 選んだステート専用ビルダーが、整合する移動とスキルを一つの `Plan` にする
4. `Plan(ステート, 行動コード, 移動, スキル, スキル文脈, 遷移理由)` を返す

通常の優先順は `Retreat → DefendOwnStone → SupportAlly → AttackEnemy → DestroyEnemyStone → Search`。性格の核である戦闘狂・寂しがり・猪突猛進は明示条件で分岐する。全候補を横断する合計点は作らない。

短時間の執着は、武器・性格に由来する敵対象フォーカス（双剣・戦闘狂など）に限る。ステートそのものを時間でロックしない。

## Execute

1. 移動を出す
2. 計画の攻撃／スキルを実行する

診断ログには、前ステート、選択ステート、遷移理由、行動コード、対象／目的地、移動・スキル開始可否、失敗理由を残す。

魔石への攻撃も、敵への攻撃と同じく計画上の攻撃手段として扱う。  
目的が魔石だからといって、Execute だけ別系統の通常攻撃を差し込む形は本線にしない。

詠唱なしスキルは移動しながら開始でき、詠唱ありは詠唱開始で移動が止まる。

## 移動失敗

到達不能・停滞が続く目的地は、短時間候補から外してよい。これは経路失敗の局所対処であり、目的選択の押し込みではない。
