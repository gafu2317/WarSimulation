# 判断の流れ

主な実装: `CombatCharacterSystem.TickAiDecisionsNow`、`CombatAiBrain`、`CombatAiPlanner`

## 目的

目的は次の6つだけ。

| 目的 | 意図 |
|---|---|
| `AttackEnemy` | 敵を攻撃する |
| `DestroyEnemyStone` | 敵魔石へ進み破壊する |
| `DefendOwnStone` | 自軍魔石を守る |
| `SupportAlly` | 味方を支援する |
| `Search` | 敵を探す |
| `EmergencyRetreat` | 危険な状態から退避する |

高所、森林、追従、遮断、待機、詠唱は目的ではなく、目的内の行動である。

## 選択ルール

1. 緊急退避を最優先する。
2. 門番、復讐鬼、便乗屋、猪突猛進、戦闘狂、寂しがりの明示条件を確認する。
3. 通常は「自軍魔石の脅威 → 支援 → 敵との交戦 → 索敵 → 敵魔石」の順で選ぶ。

武器や性格の重みを合算して目的を決めない。条件と固定順で理由を追えるようにする。

## 情報の扱い

- 直接視認: 現在の位置・状態を使える。
- 認識保持: 最後に見た情報だけを使える。
- 未認識: 実位置・実体力を判断へ持ち込まない。

味方の視界共有は認識を更新するが、見ていない間の実変化は推測しない。

## Prepare → Execute

1. チームで文脈と視界を更新する。
2. 各Brainが順にPrepareし、成功した計画を予約する。
3. 後続キャラは先行キャラの予約ダメージ・回復を参照する。
4. 全BrainがExecuteする。

Planは目的、行動、移動、技能、対象、遷移理由をまとめて持つ。
詠唱中は新しいPlanを作らず、実行時にも対象・射程・状態を再確認する。

性格固有の行動は専用ステートを増やさず、`BuildPlanForState` と対象・移動の選択へ閉じ込める。
