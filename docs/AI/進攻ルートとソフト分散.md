# 進攻ルートとソフト分散

関連: [README](README.md) · [移動](移動.md) · [進攻ルート](進攻ルート.md)

## 目的

川＋複数橋のマップで、全員が同じ橋に寄り戦闘が一点に停滞するのを防ぐ。  
AI は進攻ルート候補を使い、**担当固定なしのソフト分散**でルートを分ける。

## 方針（合意）

| 項目 | 決定 |
|---|---|
| 分散方式 | ソフト分散（減点で偏りを避ける） |
| 担当ルート | **しない**（固定割当・予約枠は置かない） |
| 対岸射撃点 | **後回し** |
| 判断パイプライン | 変えない（文脈→戦況→目的→移動→スキル） |

## 現状のギャップ

- `CombatStoneAssaultRoutes` はルート列挙できるが、AI 判断には未接続
- AI は橋 Feature の点を個別採点するだけなので、最短・低リスクに潰れやすい
- 味方の近い移動先減点はあるが、**ルート単位の偏り**は見ていない

## 目指す形

```text
マップ開始時（または NavMesh 準備後）
  → 進攻ルート候補を列挙（直進 / 橋ごと）
  → 文脈に載せる

各キャラの移動採点
  → 前進・魔石破壊などのとき、ルート上の次ウェイポイントを候補に
  → 同じルートへ味方（計画・現在地）が多ければ減点
  → 毎判断で作り直す（担当ロックなし）
```

## ソフト分散のルール

1. ルートごとに「いま使っている味方数」を見る  
   - そのルートの橋／次ウェイポイントへ向かっている計画  
   - またはその回廊付近にいる前進中の味方
2. 自分以外の味方が多いルートは減点する（人数に応じて強く）
3. 空いているルートは相対的に選ばれやすくなる
4. 脅威・詰まり・目的変更があれば、次の判断で自然にルートが変わりうる  
   （担当を持たないので再割当処理は不要）

盾の同行や支援の合流は、ルート分散より武器役割を優先してよい。

## 進攻ルート候補の使い方

[進攻ルート](進攻ルート.md) の列挙結果を AI 入力にする。

- 直進のみのマップ → 候補1本（分散の余地は小さい）
- 橋が複数 → 橋ごとの回廊が候補
- 対岸射撃用ゴールはまだ作らない

移動コードは既存の前進・橋経由を拡張する想定で、目的 enum は増やさない。

## 高所（関連・本変更の主眼外）

高所は別途、索敵だけでなく支援／妨害の射線足場としても厚くする余地がある。  
今回のソフト分散とは独立して進められる。

## 実装順（予定）

1. 進攻ルート候補を文脈へ載せる（生成は既存の薄い版を流用）
2. 魔石前進時の移動候補をルート／ウェイポイント基準にする
3. ルート単位の味方偏り減点（ソフト分散）
4. （後回し）対岸射撃点
5. （別途）高所の戦術利用強化
