# 進攻ルートとソフト分散

関連: [README](README.md) · [移動](移動.md) · [進攻ルート](進攻ルート.md)

## 目的

川＋複数橋のマップで、全員が同じ橋に寄り戦闘が一点に停滞するのを防ぐ。  
AI は進攻ルート候補を使い、**担当固定なしのソフト分散**でルートを分ける。

## 方針（合意）

| 項目 | 決定 |
|---|---|
| 分散方式 | ソフト分散（減点で偏りを避ける） |
| 担当ルート | **しない**（固定割当・予約枠は置かない） |
| 対岸射撃点 | **後回し** |
| 判断パイプライン | 変えない（文脈→戦況→目的→移動→スキル） |

## 実装の流れ

```text
マップ設定時（CombatMapSystem.SetCurrentMap）
  → CombatAssaultRouteCache を Invalidate

文脈 Collect
  → キャッシュ EnsureBuilt（自軍／敵軍それぞれの start→goal）
  → CombatAiContext.AssaultRoutes に渡す

SelectBestMove
  → 各ルートの次地点を AdvanceViaBridge / AdvanceEnemyStone 候補に
  → CombatMoveTarget に AssaultRouteKey（BridgeFeatureIndex、直進は -1）

MoveScorer
  → 前進系かつルートキー付きのとき、同じルートを使う味方数に比例して減点
```

## 次地点ルール（毎判断・担当なし）

- 入口から遠い → `EnterWorld`（`AdvanceViaBridge`）
- 入口付近／通過済みで出口から遠い → `ExitWorld`（直進ルートはスキップ）
- 出口付近／対岸 → 既存の敵魔石アプローチ点（`AdvanceEnemyStone`）
- すでにその地点にいる（距離閾値内）→ その段階の候補は出さない

## ソフト分散のルール

1. ルートごとに「いま使っている味方数」を見る
   - そのルートの Enter／Exit／（出口寄りの）魔石アプローチへ向かっている計画
   - または Enter–Exit 回廊付近にいる前進中の味方
2. 自分以外の味方が多いルートは減点する（人数に応じて強く、上限あり）
3. 空いているルートは相対的に選ばれやすくなる
4. `SupportAlly` / `InterceptThreat` には掛けない（前進系コード＋ルートキー付きのみ）
5. 目的地近傍の局所重複減点は従来どおり残す

## 進攻ルート候補の使い方

[進攻ルート](進攻ルート.md) の `CombatStoneAssaultRoutes.BuildCandidates` を流用する（アルゴリズムは変更しない）。

- 直進のみのマップ → 候補1本（分散の余地は小さい）
- 橋が複数 → 橋ごとの回廊が候補
- 対岸射撃用ゴールはまだ作らない

## 高所・対岸

対象外（いまはやらない）。
