# 進攻ルートとソフト分散

関連: [README](README.md) · [移動](移動.md) · [進攻ルート](進攻ルート.md)

## 目的

複数の進攻ルートを持つマップで、全員が同じ経路に寄り戦闘が一点に停滞するのを防ぐ。ルートが橋を含むかどうかはマップによる。AI は **担当固定なしのソフト分散**でルートを分ける。

## 方針（合意）

| 項目 | 決定 |
|---|---|
| 分散方式 | ソフト分散（現在利用者が最少のルートを選ぶ） |
| 担当ルート | **しない**（固定割当・予約枠は置かない） |
| 対岸射撃点 | **後回し** |
| 判断パイプライン | `DestroyEnemyStone` のステート内行動 |

## 実装の流れ

```text
マップ設定時（CombatMapSystem.SetCurrentMap）
  → CombatAssaultRouteCache を Invalidate

文脈 Collect
  → キャッシュ EnsureBuilt（MapDataのcornersを自軍は正順、敵軍は逆順に変換）
  → CombatAiContext.AssaultRoutes に渡す

BuildDestroyStoneMove
  → 現在位置のpolyline進捗から各ルートの次cornerを候補に
  → CombatMoveTarget に AssaultRouteKey（安定したRouteId）

  → 各ルートを使う味方数を数え、最少のルートを選択
```

## 次地点ルール（毎判断・担当なし）

- 現在位置を全線分へ投影し、最短距離の線分を現在進捗にする
- 同距離なら進捗が大きい線分を選ぶ
- 到着閾値より先にある最初のcornerを `AdvanceAssaultRoute` の候補にする
- 残りのcornerがなければ既存の敵魔石アプローチ点を `AdvanceEnemyStone` の候補にする

## ソフト分散のルール

1. ルートごとに「いま使っている味方数」を見る
   - 意図目的地がそのルートのpolyline付近にある味方
   - または現在位置がそのルートのpolyline付近にある味方
2. 自分以外の味方が最少のルートを選ぶ
3. 同数なら次cornerまで近いルートを選ぶ
4. `SupportAlly` / `InterceptThreat` には適用しない

## 進攻ルート候補の使い方

[進攻ルート](進攻ルート.md) でEditor検証され、`MapData.AssaultRoutes` に保存されたルートだけを使う。自動設定時の候補生成には `CombatStoneAssaultRoutes.BuildCandidates` を使う。

- 直進のみのマップ → 候補1本（分散の余地は小さい）
- 複数ルートのマップ → 保存された各回廊が候補（橋の有無は問わない）
- 対岸射撃用ゴールはまだ作らない
