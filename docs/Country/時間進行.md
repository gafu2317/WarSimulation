# 国家の時間進行

内部時計と日付通知の仕様を扱う。画面の形・色・文字は [国家画面のUI](UI.md#上の帯と時間操作)、月初画面の操作は [月初の政務UI](月初の政務UI.md) を参照する。

既存の `DateManager` を時計の唯一の所有者として使う。月・日と1日未満の経過時間を保持し、停止・通常進行・2倍速を管理する。新しく始めると1月1日になる。各月の日数は実際の暦に合わせ、2月は28日、12月の次は1月とする。経過月の通算値は年越し後も維持する。

| 操作 | API | 動作 |
| --- | --- | --- |
| 進行 | `Resume()` | 通常の速度で進める。重複実行しても速くならない |
| 停止 | `Pause()` | 内部の時計を止める。その日の経過分は保持する |
| 2倍速 | `ResumeDoubleSpeed()` | 通常の半分の実時間で1日進める。重複実行しても2倍を超えない |
| 経過時間の入力 | `AdvanceTime(seconds)` | `Update` から実時間を渡す。テストでも同じ入口を使う |

`_secondsPerDay` は通常進行の1日あたりの実秒数。Countryシーンでは1秒で、2倍速では0.5秒になる。`SpeedMultiplier` は停止0・通常1・2倍速2を返す。1日未満の進み具合は割合で保持し、速度変更・停止・再開でその割合を失わない。`Time.unscaledDeltaTime` を使い、`Time.timeScale` は変更しない。時計の無効化・アプリの一時停止・国家HUDの無効化でも停止する。

日付変更の入口は既存の `OnDateChanged(month, day)` と `OnMonthChanged(month)`。どちらも新しい日付を取得できる状態で通知し、月初は日次通知の後に月替わりを通知する。早送りでも `OnDateChanged` は1日につき1回発生する。通知先が `Pause()` を呼んだ場合、その場で止め、未処理の経過時間を後でまとめて進めない。

`OnProgressionChanged` は速度を含む進行状態が変わるたびに通知する。`CountryTimeControls` は日付と進行状態を購読し、上の帯の右下にある日付と選択中のボタンを更新する。「停止」「1倍速」「2倍速」の各ボタンは対応する状態を直接指定する。月初報告・襲撃・他画面で停止した場合も停止が選択される。設定から月末へ進行中は日付に「早送り中」を表示する。HUDの再有効化でも同じ `DateManager` へ接続する。

既存の `CountryCycleSystem` の月替わりの停止は維持する。固定値による仮資源加算に代わり、当月の最終日への到達時に人口比例の月次収入を加算する。既存の施設強化キューも日次通知の購読を維持する。

税収と国庫は別に管理する。月次収入の重複防止には `ElapsedMonths` を使い、12月から1月へ戻っても別の月として識別する。受取日や増加量の計算は [資源と収入](資源と収入.md) を基準にする。

旧 `StartFastForwardAsync()` と `PauseFastForward()` は廃止し、呼び出し元も新しい操作へ置き換える。Countryシーン内の旧S/Pキーのテスト入力は無効にし、HUDとカメラ操作への干渉を避ける。

月初は通常進行・2倍速とも既存の月替わり処理で停止し、報告画面を自動表示する。途中の停止では月初画面を開かない。

設定画面の「月末に飛ばす」は `AdvanceToMonthEnd()` を使い、既存の日次処理を１日ずつ通しながら基準の５倍速で進める。途中で停止・切替すると、その日までの確定した日次処理を保ち、1日未満の早送り分は破棄する。旧 `CountryTimeProgressPopup` と日めくり演出の素材は未接続で、現行UIの一部とは扱わない。過去の確認記録は [TimeProgress-v2](../../Artifacts/CountryUI/TimeProgress-v2/verification.md)、3モードの時計の確認は [TimeModes-v1](../../Artifacts/CountryUI/TimeModes-v1/verification.md)、背景なしの小さめの記号、固定幅の日付欄と三角の重なりは [TimeModes-v4](../../Artifacts/CountryUI/TimeModes-v4/verification.md) を参照する。

## 遠征の日付処理

遠征も同じ `OnDateChanged` から進める。`CountryCycleSystem` は `Expeditions.AdvanceTo`、`Roster.AdvanceTo`、最終日の収入精算の順に処理する。帰還と訓練開始が同日でも、兵士の帰還を先に反映する。未解決の到着があればその日で時計を停止し、戦闘シーンへ移る。帰還だけでは自動停止せず、月初に通常の報告へまとめる。月初と到着が重なった場合は戦闘後に報告を表示する。

`CountryDate.AddDays` は既存の月日数と経過月数を使い、遠征の日単位の到着・帰還日を求める。年越しと2月28日に対応し、負の日数は拒否する。訓練の2か月・復活の1か月には引き続き `AddMonths` を使い、固定日数へ置き換えない。遠征画面を開いた時と出発の確定後は停止し、画面を閉じても勝手に再開しない。

## 襲撃の日付処理

同じ日次通知で遠征、兵士の訓練・復活、月末精算を処理した後、`Defense.AdvanceTo` を呼ぶ。襲撃を生成したら、その日の通知内で時計を停止し、2倍速でもその場で中断する。未処理の早送り時間を後で消化しない。通常は20〜30日後の自領への襲撃を1件生成し、防衛で解決した後に次の間隔を数える。毎月1日の月初報告を優先し、襲撃日は2日へ送る。設定OFF中は襲撃を生成せず、再びONにした日から間隔を取り直す。表示と操作は [防衛編成と襲撃](UI.md#防衛編成と襲撃) を参照する。

戦闘中も国家時計は停止し、勝敗・撤退の確定時にCPと耐久を一度だけ消費する。復活予定の基準日は遠征なら到着日、防衛なら襲撃日を明示して使い、出発日や帰還日へずらさない。国家へ戻った後も停止を維持する。戦闘画面への遷移や戦場の読込・配置に失敗した場合は、同じ日付の遠征・襲撃と消耗前の状態を保持する。遠征では国で速度ボタンを押すと、その日の戦場を開き直す。防衛では同じ迎撃画面から再出撃する。

## 進行の保存と再開

ゲームに確定した日付・資源・月の精算、建設と配分、兵士の育成・性格・復活待ち、武器の所有と耐久、領地、遠征と襲撃を一組で自動保存する。国画面で時計が停止しているときは変更後に、進行中は数秒ごとに保存する。出撃を受け付けた時点と勝敗が確定した時点でも保存する。再開時は国家の画面を初期表示し、時計は停止する。時間が止まっていた間の日数は加算しない。

戦場の途中で終了した場合、到着済みの遠征は同じ出撃内容で戦闘を最初から始める。防衛は同じ襲撃と登録編成を再表示し、迎撃を選び直せる。勝敗の確定後は、結果画面を閉じる前に終了しても領地・消耗・復活予定を再適用せず、精算済みの状態を復元する。

保存形式2は精霊使役学校の補正を含む現在CPを記録する。形式1から再開するときは保存された完成済みLvを使い、残りCPがある兵士へその補正分を一度反映する。CP0と復活予定は保持する。移行後は形式2で書き込み、再読込では保存した現在CPを復元する。

端末またはブラウザーに一つの進行を保持する。直近と一つ前の保存を交互に更新し、新しい保存が壊れていたときは読める直前の保存へ戻して知らせる。無効な日付などを検出すると、保存枠と項目をログへ記録する。どちらも読めない場合は元データを残し、そのプレイ中の保存ができないことを知らせる。下書きの編成や選択中の画面、戦場の途中状態は再開対象外。
