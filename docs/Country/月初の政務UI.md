> 月初の画面は「報告 → 配分 → 建設 → 育成」の順に、下の「戻る」「次へ」で移動する。最後の「完了」で配分・建設・訓練の選択を反映して国に戻る。最初の報告画面には戻るボタンを置かない。ページ移動では配分・建設・訓練を自動確定しない。国画面の各ボタンから開いた場合は対象画面だけを表示し、「戻る」で翌月の予定を保持して国画面に戻る。月初にはその予定を再編集でき、「完了」で訓練を開始する。

2026-11-03更新。CountryシーンのuGUIで表示し、月初の自動表示と実際の収入記録へ接続する。この文書は操作要件と実装の範囲を扱う。部品の形・色・素材は [国家画面のUI](UI.md#政務画面の共通部品)、確認記録の位置づけは [国家ドキュメントの入口](README.md#確認と資料) を基準にする。

## Unityでの操作範囲

- 通常進行・2倍速のどちらでも月替わりで停止し、月末に受け取った税収・木材・鉱石の実額を報告画面に表示する。閲覧・再表示で資源を加算しない。
- 配分スライダー、国庫使用、効果詳細、強化と新築の候補、学校ごとのメンバー選択を操作できる。
- 施設の仮設定は `Assets/Data/Country/CountryGovernmentExample.asset`。現在の7施設は操作案の例。旧6人の仮メンバー選択は撤去し、訓練は `CountryRosterExample.asset` の26人と3校を使う。
- 配分・建設は最後の完了まで編集案を保持し、建設一覧の行を押して選択・解除する。完了時に操作案を保存する。保持先は `PlayDataManager.GovernmentDraft` とし、設定から独立した戦闘画面へ往復しても失わない。資源の実支出、工事の完成・建物モデルの変化、アプリ終了後の保存は未接続。訓練の選択は画面を閉じても保持し、月初の完了時にまとめて国家側データへ反映する。成長量は設定から適用する。
- `WarSim > Country > Set Up Government UI` で共通部品とシーン参照を設定する。
- 共有素材の部品、適用範囲、素材のみを更新するメニューは [UIの共有素材](UI.md#共有素材の設定) にまとめる。
- 一覧の枠・決定ボタンなどの縮小表示は [画像の縮小描画](UI.md#画像の縮小描画) に従う。画像取り込みの更新だけで、操作要件や配置を変えない。
- `WarSim > Country > Set Up Soldier UI` は兵士・武器・訓練の共通PrefabとHUDの接続だけを更新する。開いているシーンを保存・再読込しない。

設定から直接変更した人口・国庫・木材・鉱石は、既存の資源通知から政務の残高・月収見込・配分の％基準にも反映する。受取済みの収入報告は当時の入金記録を維持する。操作は [設定と資源の変更](UI.md#設定と資源の変更) を参照する。

## 遠征の帰還報告

「現在の合計量」は税収・木材・鉱石の3行とも数値だけを表示する。税収行に「国庫」の接頭辞は付けず、実際の国庫残高を表示する。

既存の収入画面を「報告」と表示し、紙面の見出しを月名を付けない「報告書」とする。報告書の紙面上に資源アイコンを添えた税収・木材・鉱石の受取額と現在の合計量の表、その下に帰還した遠征の縦スクロール一覧を置く。税収行の合計量は予定額ではなく実際の国庫残高とし、木材・鉱石の所持数とともに資源の変化に応じて更新する。紙面の素材と見た目は [月初報告](UI.md#月初報告) にまとめる。帰還した領地名・獲得結果・帰還日・人数を表示し、行を押すと全参加者と持ち出した武器を確認できる。共通の拠点画像と詳細ダイアログを使い、戻ると同じ報告へ戻る。

帰還した日から兵士と武器を使えるが、その場で報告画面を自動表示しない。2日以降の帰還は翌月1日の報告にまとめ、1日当日の帰還はその日の報告に含める。各遠征の確定した帰還日から報告月を求め、月初を越す日付のまとめ処理でも報告月をずらさない。画面を閉じたり再表示したりしても記録を消去・再追加しない。資源受取の記録と遠征の帰還記録は別に保持し、閲覧で入金・占領・帰還を再実行しない。

到着日の戦闘はスキップし、参加者全員のCPを20消費する。暫定の戦闘時CP消費量は帰還報告の詳細に表示せず、報告の再表示では再消費しない。襲撃は月初報告と重ならない日に発生し、専用ポップアップで対応する。詳細は [防衛編成と襲撃](UI.md#防衛編成と襲撃)。

遠征自体の選択と移動は [遠征](UI.md#遠征)、訓練との排他は [兵士と訓練](兵士と訓練.md#遠征との排他) を参照する。

## 適用する月

- 予算・育成・建設は、毎月1日に決定する場合は当月、2日以降は翌月1日から適用する。判定は `CountryDate.PlanningStart` を共用し、12月から翌年1月への切替にも対応する。
- 配分・建設の見出しは「今月／来月」と対象月を示す。3画面のフッター、決定ボタン、詳細・確認画面でも適用日を確認できる。収入画面は実際に受け取った当月の記録を表示する。
- 翌月の予定残高には、まだ受け取っていない今月末の収入見込を含める。すでに今月分が入金済みなら重複加算しない。これは操作案の見積もりで、実際の資源残高へ加算する処理ではない。
- 育成は翌月開始を「訓練予約」と表示し、開始日と2か月後の完了日を確認して確定する。予約中は定員を確保し、開始日までは出撃可能。開始前にCP0になったら予約を解除して復活待ちにする。

報告画面のヘッダーは実際の国庫残高を「国庫」として表示する。配分・建設・育成では「計画後国庫」として操作案による見込みを示し、報告の実残高と区別する。

政務内の資源量・受取額・金額は、HUDと共通で99,999を超えたら `99999+` と表示する。配分の基準額・上下限・費用・不足額も同じ表記を使い、スライダーの割合、配分や建設の判定は省略前の実値を使う。表示規則の管理元は [資源の表示](UI.md#上の帯と時間操作) と [資源と収入](資源と収入.md#初期値と表示)。

## 配分

- 原則として適用月の税収を各施設へ振り分け、残りは国庫へ入れる。翌月の税収見込は現在の人口に基づく月収額を表示する。
- 国庫のお金も配分に使える。国庫を使う設定の初期値はオフ。横スイッチのつまみ・OFF／ON・色で状態を示す。集計は税収・施設への配分・国庫への残額または国庫からの補填を分ける。
- 各施設に最低必要額があり、スライダーの下限をその額にする。
- スライダーで配分を調整する。目盛りは0円を0％、適用月の税収を100％とする。「国庫も使う」がONなら税収＋国庫を100％とし、入金済みの税収を二重加算しない。他施設への配分や建設案で基準額は減らさない。0・25・50・75・100％の整数表示と5％刻みの小目盛りを使う。つまみ・塗りは基準額に対する配分額の割合とし、最低必要額と残り資金による配分上限の範囲で動かす。基準額が0なら操作を無効にする。配分額・最低額・配分可能額は金額で示す。つまみは全施設で同じ小さなコイン画像を共用し、減らした後も上限内で再び増やせる。
- 目盛りの下に最低額〜上限額と100％に当たる金額を表示する。目盛り下の金色の帯は現在調整できる区間とし、上下限で止まる理由を示す。割合の分母や最低額の規則は変更しない。
- 施設ごとの配分スライダーを縦に並べ、一覧をスクロールする。税収・配分合計・残額と確定ボタンは固定する。 確定ボタンには封蝋付きの支払指令書の共用画像を使い、当月・翌月の表示と従来の確定処理を維持する。
- 施設欄は確認済みの役割を短く示し、押すと適用日・最低額・今回額・追加額と役割を確認する。2026-11-03の指定により、追加配分の具体的な数値効果は後で決める。未接続の係数を訓練効果100％→150％などの実効値として表示しない。
- 適用月の税収、配分合計、国庫へ回る残額、国庫から使う額を混同しない表示にする。

入金と配分を接続するときの精算上の注意は [資源と収入・配分との接続状況](資源と収入.md#配分との接続状況) を基準にする。

## 建設

- 新たな施設の建築と、既存の建物の強化を扱う。
- 施設は1種類につき1棟まで。建築済みの種類は強化、未建築の種類は新築にのみ表示し、両方の一覧に同じ種類を出さない。
- 切り替えは「強化 → 新築」の順。初期表示は強化とする。
- 施設候補の一覧は縦スクロールとし、矢印によるページ送りは設けない。詳細表示と決定ボタンは固定する。
- 建築中の種類も重ねて建築できない。完成するまでは強化の対象にしない。
- 建築または強化に必要な時間・費用と、確認済みの施設の役割を表示する。学校の強化は定員と習得対象の学校Lvの変化を示す。他施設の未指定の個別効果や追加配分の数値効果は作らない。
- 新築・強化の工期は月単位で扱い、「1か月」「2か月」のように表示する。
- 建築場所は選ばない。対象施設の内容を確認し、「建設する」「強化する」で決定する。 決定ボタンは木の看板の共用画像を使い、当月・翌月の操作と有効・無効を同じ部品で表示する。形と押下演出は [建設の決定ボタン](UI.md#建設の決定ボタン) を参照する。

## 育成

- 兵士の初期状態・成長・CP・復活と実装上の仮設定は [兵士と訓練](兵士と訓練.md) を基準にする。
- レイアウトは [UIの一覧と詳細](UI.md#一覧と詳細の共通構造) に揃える。訓練へ入れる兵士のアイコンを上段の横スクロール列に置き、下側は左の1列の兵士一覧と、右の1人分の立ち絵・詳細にする。
- 立ち絵枠は1：2。ステータスはCP・最大HP、STR・INT、FAI・AGIの2列×3段とし、項目名と合計値だけをコンパクトに表示する。CPは現在値／上限。基礎・訓練・装備の細かな内訳を表示せず、能力値の計算は変更しない。
- 各学校に訓練する兵士を配属し、時間経過で継続訓練する。
- 訓練期間は2か月。開始・予約の確定後は内容を変更・キャンセルできない。予約は開始前でも変更不可となることを、確定前の本文と通常の補足に明記する。対象の兵士・学校・期間を確認して確定する。開始・予約のボタンは訓練旗の共用画像とし、旗面・支柱・本アイコン・文字を分ける。文字は「今月の訓練を開始／来月の訓練を予約」を一行で示す。教本の形は撤回済み。
- 1日は即開始、2日以降は翌月1日開始の予約。上段で訓練中・予約・選択中の人数を分ける。予約した兵士の開始日と訓練中の完了日・進捗は、対象を選んで右の詳細で確認する。予約だけでは訓練の進捗・成長は進まない。
- 上段の空き枠は共通画像の点線の丸で示し、選ぶと円形の兵士アイコンで埋まる。上段はアイコンだけとし、兵士名・状態・武器名と長方形のカード面を表示しない。選択中は金色の円形の縁で示し、押すとその兵士の詳細へ切り替わる。人数・横列・左一覧／右詳細は遠征の編成と同じ `CountryRosterSelection.prefab` を使い、アイコン下の武器名は遠征・防衛で表示する。一覧行・円形の縁・立ち絵枠は [兵士選択の共用画像](UI.md#兵士選択の共用画像) を使い、押下時の人物と文字の動きを分ける。
- 学校レベルに応じた定員内で兵士を選ぶ。Lv1〜5と定員3〜7人の対応は [兵士と訓練の定員表](兵士と訓練.md#学校レベルと訓練定員) を参照する。
- 配属先の2職のスキルを両方学ぶため、習得する職業を一方だけ選ぶ操作は設けない。装備武器で習得対象を切り替えない。
- 上段の右側に「学ぶ技と効果」を置き、左側の丸アイコン列は横スクロールを保つ。現在の学校Lvで扱う両職の技・習得済み状態・効果を共通のスクロール可能な詳細へ表示する。学校の変更に追従し、兵士の装備で学習対象を切り替えない。
- 学校レベルに応じた習得対象を表示する。初期習得は [既存の通常攻撃6種](兵士と訓練.md#初期スキル) のみ。
- 学校レベルごとに各武器1種類ずつ追加される習得枠を表示する。技の割り当ては [仮の習得テーブル](兵士と訓練.md#技の仮割り当て) を使い、不足分は表示しない。
- 習得済みスキルは武器種のアイコンと見出しで分類し、現在の装備で使用できる技を区別して表示する。武器変更時に習得履歴は失われず、使用可能な技が切り替わる。
- 訓練先は戦士学校・魔法学校・教会。精霊使役学校は精霊施設であり、学校の訓練先に含めない。配分・建築の対象には残す。
- 学校の表示切替や画面の開閉で、兵士の配属と進捗を失わない。
- 訓練中・CP0・遠征中の兵士は出撃不可。理由の表示と判定は [兵士と訓練・出撃条件](兵士と訓練.md#出撃条件と訓練状態) に揃える。以前の訓練停止・再開案は取り下げ、途中変更・キャンセルの操作を設けない。

## 未確定

- 各施設の最低必要額と、追加配分による具体的な効果・係数。
- 最低必要額の合計が適用月の税収を超えたときの扱い。
- 新築・強化の費用、具体的な工期の月数、段階ごとの効果。
- 同時配属・完了後の再訓練などの正式方針。現在の仮動作は1人1校、2か月で終了し自動で再訓練しない。
- 配分・建築費を実残高へ反映する確定時点と精算方法。

操作案に使う金額・工期・効果量と、26名の仮名・仮ステータスは正式データとして採用しない。訓練人数・期間・初期スキルなど、ユーザーが確定したルールとは区別する。

## 操作の流れ

- 月初は「報告・配分・建設・育成」の順に下の戻る・次へで移動する。通常時は該当画面を直接開き、ページ送りを表示しない。
- 下の決定ボタンは現在の内容だけを決定する。報告画面には決定操作を置かない。左下の「国へ戻る」で閉じる。
- 配分・建設・育成に操作の順を示す短い案内を置く。建設は左の施設一覧、右の内容確認、下の決定ボタンの順に読む。
- 選択中の対象は、別の操作を押している間も分かるようにする。押下反応の仕様はUIの共通部品にまとめる。

文字と枠の間隔は [文字の配置と余白](UI.md#文字の配置と余白) に従い、表・施設一覧・詳細・決定ボタンごとに調整する。指令書の封蝋、訓練旗の支柱と切り欠き、建設看板の留め具を避けて、アイコンと文言を一組で揃える。当月／翌月への文言変更や長い参加不可理由、確認文も実画面で確認し、本文は固定操作に重ねずスクロールで読めるようにする。[TextLayout-v1](../../Artifacts/CountryUI/TextLayout-v1/verification.md)に確認範囲を記録する。見た目の採用はユーザー確認待ち。
