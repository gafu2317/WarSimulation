# 戦闘スキル

`docs/game.md` の「技」設計と、現在のコード実装をまとめる。数値（射程・係数・CT）は [スキル射程・威力.md](スキル射程・威力.md)。見た目は [スキル演出.md](スキル演出.md)。

## 前提

- 通常攻撃も含め、戦闘中の行動はすべて `SkillBase` 系のスキルとして扱う。
- 戦闘時に使えるスキルは、装備中の `WeaponKind` に一致するものだけとする。
- スキルの習得管理と、武器が個別に付与するスキルは分離する。
- この文書は判定・効果・実行基盤の設計を扱う。演出とバランス数値は上記の別文書へ。

## 基本構造

使える `SkillId` は以下の合成で決まる。

```text
使える SkillId
  = (キャラ習得済み ∩ RequiredWeaponKind == 装備Kind)
  ∪ (武器付与 ∩ RequiredWeaponKind == 装備Kind)

↓ CombatSkillFactory

Character.AvailableCombatSkills
```

| 層 | 役割 | 主な型 |
|----|------|--------|
| マスタ | 技ID・必要武器種・将来用施設Lv | `SkillId`, `SkillDefinition`, `CombatSkillCatalog` |
| キャラ習得 | 国家シミュ側の習得スキル | `Character._learnedSkillIds` |
| 武器個体 | 武器固有で付与されるスキル | `WeaponConfig._grantedSkillIds`, `WeaponBase.GrantedSkillIds` |
| ランタイム | 実際に使うスキル一覧 | `Character.AvailableCombatSkills` |

## 実行フロー

```text
CombatAiContext
  └─ CombatAiAssessmentBuilder
       └─ CombatAiPlanner
            ├─ Objective scoring
            ├─ Move candidate scoring
            └─ Skill candidate scoring
```

- `CombatAiPlan` は `plan.Skill` と `plan.SkillContext` を保持する。
- クールダウンは `CombatSkillCooldowns` が管理する。
- 詠唱は `CombatSkillCaster` が管理し、完了時に効果適用とクールダウン開始を行う。
- AI の実行主体は `PersonalityBase` ではなく `CombatAiPlanner`（詳細は [AI/README.md](AI/README.md)）。

## 詠唱

- 範囲効果、拘束、継続効果、無敵、強制移動、大回復、大威力攻撃など、戦況を大きく変えるスキルは個別の詠唱時間を持つ。
- 通常攻撃と `Rosary_DistantHeal` は詠唱せず即時実行する。`Sword` / `Shield` のスキルも詠唱0秒。
- 詠唱開始時に移動を停止し、詠唱中はAIの再行動と移動命令を受け付けない。
- 開始時に対象、地点、対象一覧、距離、実効ステータス、未認識ダメージ補正を固定する。
- 開始後に対象が視界・認識・射程から外れても、固定した対象へ発動する。
- 範囲・全体スキルは開始後に対象を追加・再検索しない。
- 被ダメージと開始後のBindでは中断しない。術者の戦闘離脱、戦闘終了、リセット時だけ破棄する。
- 対象が戦闘離脱した場合は不発になるが、詠唱完了扱いとしてクールダウンを開始する。
- クールダウンは詠唱完了後に開始する。

## 実装済みスキル

### 杖

- `Wand_Bolt`: 単体魔法攻撃（距離依存）
- `Wand_ArcaneBlast`: 単体高威力魔法攻撃
- `Wand_AreaBlast`: 指定地点の範囲攻撃
- `Wand_GodsHand`: 単体超高威力攻撃

### 魔導書

- `Grimoire_Bolt`: 単体魔法攻撃
- `Grimoire_StrDebuff` / `StatDebuff_INT` / `StatDebuff_FAI` / `StatDebuff_AGI`: 能力デバフ
- `Grimoire_Bind`: 行動不能を含む拘束
- `Grimoire_Poison`: 継続ダメージ
- `Grimoire_Stealth`: 自己不可視

### 聖書

- `Bible_Smite`: 単体攻撃
- `Bible_StrBuff` / `Bible_IntBuff` / `Bible_FaiBuff` / `Bible_AgiBuff`: 能力バフ
- `Bible_Invulnerable`: 一定時間ダメージ無効
- `Bible_Gotsume`: 被弾反射バフ
- `Bible_CarryRush`: 味方を連れて高速移動

### ロザリオ

- `Rosary_Strike`: 単体攻撃
- `Rosary_DistantHeal`: 距離依存の単体回復
- `Rosary_CloseHeal`: 単体大回復
- `Rosary_Regeneration`: 継続回復
- `Rosary_HealingArea`: 地点設置の回復エリア
- `Rosary_SacrificeThunder`: 自傷つき認識敵全体攻撃

### 近接

- `Sword_Slash` / `Shield_Slash`: 通常攻撃
- `Shield_ShoulderGuard`: 味方の被弾肩代わり

## 認識

- 敵対象スキルは、見えている敵に加えて認識中の敵も対象にできる。
- 認識は「自分が見た情報」と「味方から共有された情報」の両方で更新される。
- 最後に情報を得てから 5 秒は認識を保持する。
- ステルスで見えなくなっても、認識保持中は対象に含まれる。

## 計算式

- 直接攻撃/単体回復の基本式は `実効ステータス × スキル係数`。
- 実効ステータスは `(キャラ基礎ステータス + 武器の主ステ補正) × バフ/デバフ倍率`。
- 武器はダメージそのものを持たず、対応する主ステータスを上げる。

個別の射程・係数・CT・目安ダメージは [スキル射程・威力.md](スキル射程・威力.md)。

## 基盤の現仕様と制約

実装済みの基盤:

- 単体攻撃 / 単体回復 / 単体バフ・デバフ
- 範囲攻撃 / 全体攻撃 / 地点設置
- 継続効果 / 状態異常 / 無敵 / ステルス（最小）
- クールダウン、武器種制限、習得と武器付与の合成
- `SkillExecutionContext`（単体・地点・複数対象）
- 認識済み敵を対象に含める敵対象基盤
- 距離依存ダメージ・回復（杖通常・遠隔癒し）

制約・正規仕様メモ:

- `Area` は「地点指定かつ対象必須」の範囲スキルとして扱う。設置系は `Point` 前提。
- 継続効果は実装済みだが、効果種別はまだ必要最小限。
- ステルスは発動時に敵の認識を解除し、新規視認を阻害し、攻撃で解除される。
- `Rosary_SacrificeThunder` の HPコストは専用コスト処理ではなく通常ダメージとして自身に適用する。そのため `Invulnerable`、`IncomingDamage`、肩代わりなど通常ダメージに作用する仕組みの影響を受ける（暫定ではなく現在の正規仕様）。

## 今後の拡張

すでに動いている距離依存・設置・同行移動・AIスキル選択の「有無」ではなく、深掘りや定義側の整理が残課題。

### SkillDefinition の拡張候補

今の `SkillDefinition` は情報が少ない。今後は少なくとも以下のどれかが必要になる可能性がある。

- 対象タイプ、発動タイプ、最大射程、効果半径
- 持続時間、効果間隔、射線要否、HPコスト
- 距離補正タイプ、自己中心か指定地点中心か

### 残っている設計課題

- 射線要否のスキル定義化（単体直撃は LoS 必須、射線不要範囲魔法は不要、など）
- 認識・不可視の詳細化（認識済みか、いつ認識したか、攻撃で解除するか）
- コスト系スキルを増やす場合、通常ダメージ扱いを続けるかの方針
- 効果適用の共通化（対象決定・条件判定・効果適用の分離、攻撃/回復/範囲検索/状態異常ヘルパ）
- AI 側の優先順位・範囲価値・回復判断・奇襲・バフ維持・HPコスト判断の精度向上

優先して定義側を厚くしてから、射線要否・認識詳細・AI判断の順で広げる。
