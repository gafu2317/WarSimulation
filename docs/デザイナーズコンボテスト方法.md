# デザイナーズコンボテスト方法

## 目的

デザイナーズコンボが、強いキャラクターを並べただけではなく、互いの弱点を補うことで有利になっているかを確認する。

勝率だけでは判定しない。狙った連携が実際に発生したか、その連携が勝利条件へどれだけ寄与したか、連携を崩されたときに性能が下がるかを合わせて見る。

## 比較する編成

各コンボについて、人数、武器、能力値、スキル、初期位置をそろえ、性格だけを変えた次の編成を比較する。

- 連携あり: 記載どおりの武器と性格を使う。
- 片側解除: 連携の片方だけを標準性格へ変更する。複数の中核がある場合は一人ずつ変更する。
- 通常編成: 同じ武器と人数で、連携を狙わない性格を使う。
- 対抗編成: 分断、後衛への接近、範囲攻撃など、その連携の弱点を狙う。

片側解除との比較を最も重視する。これに勝てなければ、強さの原因は連携ではなく武器やキャラクター単体にある可能性が高い。

## テスト手順

### 1. 行動確認

- 同じ条件で5試合行い、戦闘記録と実際の画面を確認する。
- 狙った二人以上が同じ対象、位置、時間を利用しているかを見る。
- 連携が起きない場合は、勝率を測る前に対象選択や同行処理を直す。

### 2. 比較試合

- 連携あり、片側解除、通常編成を、同じ地形と乱数シードで各30試合行う。
- 同じシードで陣営と初期位置を入れ替えた試合も行う。
- 地形、乱数シード、陣営入替が同じ試合同士で、連携ありから比較編成の値を引く。
- 主指標は総量と毎秒値を記録し、差の平均、中央値、ばらつき、95%信頼区間を見る。
- 開けた地形、森林が多い地形、橋や狭路がある地形を含める。
- キャラクターの能力値、武器、スキル構成、魔石体力、制限時間は固定する。
- 結果が判定基準の前後5ポイント以内に収まる場合は、各100試合まで増やして再判定する。

### 3. 人数追加

- 最小構成から始め、一人ずつ追加する。
- 比較側にも同じ武器と能力値のキャラクターを追加し、人数差を作らない。
- 一人追加するごとに連携の主指標がどれだけ増えたかを見る。
- 追加しても主指標が増えない、対象変更や密集が増える場合は、その人数を有効上限とする。

### 4. 対抗試合

- コンボごとに定義した弱点を狙う武器と性格の対抗編成を使う。
- 対抗編成によって連携の発生時間と主指標が下がるかを見る。
- 対抗しても性能がほとんど下がらない場合は、連携ではなく常時有利な編成になっている可能性を疑う。

## 共通記録

- 勝敗
- 戦闘時間
- 魔石へ与えたダメージ
- 生存時間と離脱時刻
- 与ダメージ、有効回復量、有効防御量
- 攻撃対象と支援対象の変更回数
- 連携相手との距離を保っていた時間
- 拘束、毒、強化、能力上昇が有効だった時間
- 連携が崩れた時刻と原因
- 主指標の毎秒値

毎判断の全数値は保存せず、対象変更、状態の開始と終了、撃破、魔石攻撃、戦闘終了時の集計を記録する。

## コンボごとの主指標

| コンボ | 主に確認する値 |
|---|---|
| 魔石強襲 | 猪突猛進の杖が魔石へ与えたダメージ、最初の魔石攻撃後の生存時間 |
| 拘束追撃 | 拘束中に双剣が与えたダメージ、拘束中に倒した敵数 |
| 前線突破 | 双剣が盾または聖書の支援範囲内で追跡した時間、追跡対象の撃破数 |
| 囮砲撃 | 盾を狙った敵数、杖の範囲攻撃が同時に当たった敵数 |
| 囮維持 | 複数の敵に狙われた盾の生存時間、盾への有効回復量 |
| 毒籠城 | 毒の有効ダメージ、毒を受けた敵が魔導書へ到達するまでの時間 |
| 遠隔支援付き一匹狼 | 単独交戦を維持した時間、遠隔回復量、単独交戦中の撃破数 |
| 陽動魔石強襲 | 陽動中に魔石から離れた敵数、その時間内の魔石ダメージ |
| 恋人追従部隊 | 下世話の能力上昇時間、恋人離脱後に失った戦力 |
| 異性護衛 | スケベの能力上昇時間、能力上昇中の有効支援量 |
| 分散狩り | 双剣ごとの攻撃対象の重複率、担当した敵数、対象変更回数 |

## 判定

次をすべて満たすものを、有用なデザイナーズコンボとする。

- 行動確認の5試合中4試合以上で狙った連携が発生する。
- 連携ありの主指標が、片側解除より15%以上高い。
- 連携ありの勝率が、片側解除と通常編成より10ポイント以上低くならない。
- 中核役または補助役を失った後、主指標が明確に下がる。
- 少なくとも一つの対抗方法で、連携の主指標を20%以上下げられる。

基準値は最初の一巡後に見直してよい。ただし、結果を見て特定のコンボだけが通るように個別変更しない。

## 実施方法

- 行動確認は、既存の戦闘AIイベントログと画面確認を使う。
- 比較試合と人数追加は、実際の移動、射線、詠唱時間が必要なため、再生モードの自動戦闘で行う。
- 採点処理や対象選択の単体確認は編集モードテストへ分ける。
- 戦闘終了時に共通記録とコンボ別主指標を集計できる開発専用記録処理を追加する。
- 地形生成とAIの無作為選択を一つの戦闘シードから生成し、同じシード、編成、初期位置なら同じ試合を再実行できるようにする。
- ダメージ、回復、状態変化は、発生元のキャラクターとスキルを保持した戦闘結果から集計する。
- 範囲攻撃の命中数は同じ描画周期のダメージ数ではなく、一回のスキル実行結果に含まれる命中対象数から集計する。
- 状態の終了は定期監視で推測せず、解除または時間切れの状態変化通知から記録する。
- 対象変更は、スキル完了結果ではなくAIが選んだ攻撃、支援、追跡、魔石の対象から記録する。
- 連携発生は主指標が一度増えたかではなく、コンボごとに定めた役、対象、位置、時間の条件で記録する。
- 連携崩壊はコンボごとに必要な役の離脱と距離条件で判定し、離れることが目的の編成では距離超過を崩壊にしない。

## 実施順

1. 少人数で成立し、結果を読みやすい拘束追撃と毒籠城を確認する。
2. 同行と遠隔支援を使う魔石強襲、前線突破、遠隔支援付き一匹狼を確認する。
3. 敵の対象選択を使う囮砲撃と囮維持を確認する。
4. 二地点の同時行動が必要な陽動魔石強襲を確認する。
5. 人数と関係情報に依存する恋人追従部隊、異性護衛、分散狩りを確認する。

## 自動実施

1. Unityの `Tools/War Simulation/Designer Combo Tests/Create Or Repair Test Scene` で専用シーンを作成する。
2. `Tools/War Simulation/Designer Combo Tests/Open Test Window` を開く。
3. コンボ、試験範囲、基準シード、制限時間、時間倍率を選んで試験を開始する。

専用シーンは `Assets/Tests/DesignerCombos/Scenes/DesignerComboBenchmark.unity` に作成される。既存の戦闘シーンを雛形として使うが、検証用の実行処理は専用アセンブリに分離する。

試験範囲は次のように対応する。

- 行動確認: 開けた地形で連携ありを5試合実行する。
- 比較試合: 3地形、30シード、陣営入替で連携あり、片側解除、通常編成を比較する。結果が判定基準の前後5ポイント以内なら100シードまで自動延長する。
- 100試合比較: 最初から100シードで比較する。
- 人数追加: 最小構成から指定役を3人まで追加する。
- 対抗試合: コンボごとに定義した対抗役の編成と比較する。

結果は `Logs/DesignerComboTests` にJSONとCSVで保存する。JSONには試合別集計、対応する試合同士の差、対象変更、状態開始と終了、撃破、魔石攻撃、連携崩壊、判定結果を含める。
