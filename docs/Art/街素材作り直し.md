# 街素材の作り直し

## 再整理の状態

2026-10-22、施設が一般住宅の変更版に見えること、部材の不自然な貫通・意味のない柱・施設固有の小物不足の指摘を受け、制作条件を再整理した。
整理後、「それを踏まえてもう一度全ての3Dモデルを作り直して」という指示を受け、全素材を再制作した。剣と魔法のRPG向けの手描き調テクスチャへ改め、141モデルの原本・パーツ用PNG・確認画像を納品フォルダへまとめた。

以前の「確認済みの制作方針」には、利用者の直接の要求と制作側の設計判断が混在していた。今回は両者を分ける。

## 利用者から直接指定されたこと

- 対象は街の建物・道路・植栽・小物すべて。書斎・戦闘用モデルは対象に含めない。
- 既存素材の名前から新規制作する。旧モデルの外観を参考にしない。
- 世界観は中世ヨーロッパ・ファンタジー。適度にデフォルメし、過度なローポリ感を避ける。写真のようなリアルさは求めない。
- テクスチャもゲームの「剣と魔法のファンタジー」として表現する。普通の中世建築に見える質感から改める。
- 細かな部品・汚れ・質感はテクスチャを活用し、何でも細かな立体の組み合わせにしてポリゴン数を増やさない。
- テクスチャはパーツごとに作って組み合わせる。建物全体の一枚絵にはしない。
- 窓は窓として、露店の商品は何を売っているか分かるように、丁寧に作る。
- 役割を持つ施設は、一般住宅のマイナーチェンジではなく、全く異なる特別な建物として作る。
- 施設は遠目でも役割が分かるようにする。大きなシンボル、異なる色や形などは、そのための手段。
- 建物の形もできるだけ特徴的にする。ただし、違和感のある変な形にはしない。
- 不自然に部材が貫通したり、意味の分からない柱があったりする状態を直す。
- 役割のある建物には、用途固有の小物・設備を十分に用意する。
- 街づくりに不足する小物や露店等も追加する。
- 納品は `.blend`、テクスチャPNG、全モデルの正面確認画像をまとめたフォルダ。

## 過剰に広げていた解釈の修正

| 元の指定 | 制作側の誤った解釈・固定 | 今回の整理 |
| --- | --- | --- |
| 特徴的だが変な形にはしない | 住宅に近い無難な形から離れない | 用途に根拠のある大胆な建築構成を作る。棟・塔・回廊・中庭・大屋根などで、住宅とは別の建物にする |
| 細かな部分はテクスチャを使う | 必要な立体や固有の小物も減らす | シルエット・奥行き・用途の判別に必要な形は立体で作り、表面の細部をテクスチャで表す |
| ポリゴン数を抑える | 一律の数値上限を外観品質より優先する | 不要な分割・見えない面・細部の過剰な立体化を減らす。数値上限は制作側の暫定値で、利用者が指定した条件ではない |
| 一般住宅の出来はよい | その本体を施設にも流用する | 一般住宅に対する評価。施設の建築構成を住宅へ揃える根拠にはしない |
| 大きなシンボルや異なる色・形で識別する | 住宅へ大きな看板を付ければよい | 建築本体・用途固有の設備や小物・シンボルを合わせて識別できるようにする |
| 自然な外観にする | シンボルは入口か破風だけ、屋根色も施設ごとに固定する | 設置場所や色は設計案。取り付け方や全体の調和を確認し、用途ごとに決める |
| 旧モデルを参考にしない | 既存の形を避けること自体が設計目的になる | 名前と用途から新しく設計する。建物の用途や建築の仕組みを理解して作ることは必要 |

「道具そのものを巨大な建物の形にする方式は採らない」という以前の記述も、制作側が加えた一律の制限だった。
利用者の指定は「特徴的だが、変な形にはしない」。案ごとの自然さを判断する条件として扱い、未指定の禁止事項を増やさない。
旧資料の外観・色・配置・寸法等も、旧作の記録と現在のゲーム上の要件を区別し、新しい外観の制約へ自動的に持ち込まない。

## 両立させる品質条件

- 遠景では建物本体の輪郭・構成・色で施設を区別できる。看板を隠しても一般住宅の変更版には見えない。
- 近景では施設固有の設備・道具・商品・装飾から用途が伝わる。数合わせの無関係な小物では埋めない。
- 柱は梁・屋根・庇等との関係が分かり、塔や屋根には支持する構造がある。窓や入口を無関係な部材が塞がない。
- 接合に必要な部材の重なりと、見た目が破綻する貫通を区別する。「全メッシュを一切交差させない」という新しい制約にはしない。
- デフォルメによって形や色を読みやすくしつつ、窓・扉・商品・素材はそれぞれ何か分かるように作る。
- 素材・窓枠・扉などの部品は共用できる。完成した施設の建築構成まで住宅と共通にしない。

識別性、用途の表現、構造の自然さ、丁寧な仕上げは、どれかを捨ててよい条件ではない。効率化はそれらを満たす形に対して行う。

## 再整理前の実装で確認した原因

再整理前の `Tools/Blender/MedievalCityV2/build_assets.py` は、住宅と多くの施設の本体を共通の `hall()` で作り、塔・庇・小物や `facility_identity()` の紋章を追加する構成になっていた。
このため、用途から異なる建築を設計する前に住宅と似た本体が決まり、後付けの部材も本体との納まりを十分に確認できていなかった。

現在の自動検査は、保存・画像参照・UV・接地・ポリゴン数等を確認するもので、柱の意味や部材の不自然な貫通、施設の識別性を保証していない。
技術的な検査の合格を、造形の完成と扱わない。

## 納品時の状態

初回の簡略版と紋章追加版は品質不足のため完成品として扱わない。
再制作では `facility_buildings.py`、`service_buildings.py`、`landmark_structures.py` に用途ごとの建築構成と設備を用意し、旧来の住宅流用・紋章後付け処理を削除した。
植栽には葉の房と葉の塊の表面用PNG、花には花弁用PNGを用意し、商品の外形、道路の接合、橋のアーチ・桁も再制作している。
石・木・三色の屋根・扉・舗装を、広い筆の陰影と暖色の縁・寒色の影を持つ部材用PNGへ再制作した。教会の聖紋、魔法学校の星と軌道、精霊学校の蔓と花は専用装飾帯とし、ガラス・葉・花・草・岩も同じ世界観へ合わせた。これは制作側の具体案であり、新しい一律の禁止事項にはしない。

- 原本はマスター1点と個別141点。元の街素材91名称と追加50点を含む。
- パーツ材質は101種類、BaseColor・Normal・Roughnessの計303PNG。画像生成した22部材の原画像とプロンプトも同梱した。
- 正面141点・斜め141点・補助上面26点の計308画像を目視した。
- 保存済みマスターの実形状・UV・PNG参照・接地を検査し、個別141ファイルも開き直した。
- 原本・PNG・確認画像のSHA-256と一覧の照合が完了した。各検査の範囲と結果は納品フォルダの`Reports/`へ保存した。
- `index.html`で分類・名前による絞り込み、正面・斜め・補助上面の切り替えができる。

## 用途から設計を考える例

以下は方向を説明する例で、確定した形状・色・小物一覧ではない。

| 施設 | 自然な建築構成と目印 |
| --- | --- |
| 教会 | 高い身廊・低い側廊・鐘楼・礼拝用の前庭。鐘や宗教的な意匠も用途に合わせる |
| 戦士学校 | 訓練場を囲む校舎・武器庫・門。訓練人形、標的、武具棚などを使う場所へ置く |
| 魔法学校 | 研究塔・講義棟・実験用の庭を持つ学舎。観測器具や研究設備などを用途に合わせる |
| 精霊使役学校 | 庭・回廊・儀式や育成のための空間を中心にした学舎。精霊との関わりが伝わる設備を考える |
| 図書館 | 大きな閲覧空間を持つ棟・書庫・入口の構成。閲覧や本の扱いに関わる設備・意匠を加える |
| 鍛冶屋 | 炉と煙突を中心にした工房・開いた作業場。金床、工具棚、素材置き場、冷却槽などが仕事の流れとして並ぶ |

| 天文台 | 観測塔・ドーム・観測用の開口や足場。観測器具を実際に使える位置へ置く |
| 倉庫・穀物庫・厩舎 | 保管、荷役、防湿、馬の世話などの用途が、建築本体と周辺設備の両方に表れる |
