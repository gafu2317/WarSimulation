# 新旧モデルの種類統一調査

2026-10-22時点のPrefab、旧Blender原本、生成・書き出しスクリプトを照合した。

調査後、ユーザーの制作指示により不足50モデルの制作・材質ベイク・Unity取り込み・Countryへの配置まで完了した。新旧とも141モデルを保持する。比較シーンは追加指示に合わせ、学校のLv1〜4を除いた129種類を同数ずつ使う構成に更新した。学校は戦士・魔法・精霊のLv5を各1棟とし、建物や小物は城壁内に収めた。川は中央寄りを流れ、水門を通って城外へ続く。水車は本流に沿う向きとし、正面向きの対象には含めない。現在の構成と操作は [城壁都市比較](../Country/城壁都市比較.md)、取り込み結果は [unity_import_validation.json](../../Artifacts/CountryComparison/LegacyParity/unity_import_validation.json) を参照する。

以下は制作前に行った調査と、制作に採用した方針の記録である。「未実施」などの記述は調査時点を指す。

## 不足数

旧セットは91、新セットは141モデル。旧91モデルはすべて新セットにも存在するため、追加する対象は50モデルで一意に決まる。

| 区分 | 旧側に不足 | 旧原本に同名素材あり | 独立化・派生制作・新規造形 |
| --- | ---: | ---: | ---: |
| 建物 | 5 | 0 | 5 |
| 露店 | 8 | 0 | 8 |
| 小物 | 27 | 7 | 20 |
| 柵・橋・階段など | 10 | 5 | 5 |
| 合計 | 50 | 12 | 38 |

学校のLv1〜5、植栽・岩24モデルは、種類としてはすでに両セットに存在する。Countryシーンで未使用の75モデルと、旧セットに存在しない50モデルは別の集計である。

## 取り込みだけで補える12モデル

`ArtSource/Blender/Kingdom/FantasyTownProps.blend` 内に、次の同名コレクションが存在し、それぞれにメッシュと旧材質が入っていることをBlenderで確認した。

- 柵・塀：`Fence_Panel`、`Fence_Post`、`Fence_Gate`、`Stone_Wall`、`Stone_Wall_Corner`
- 小物：`Crate_Open`、`Grain_Sack`、`Produce_Basket`、`Planter`、`Drain_Grate`、`Bollard`、`Bucket`

これらは新モデルを旧風に作り直す必要がない。旧原本の形と材質を保って、同名のFBX・Prefabとして取り込める。

## 旧方式の内容

旧セットは、Pythonで梁・板・石・アーチ・屋根・窓などを組み、Blenderのノイズやレンガ模様で材質を作る方式を持つ。代表的な旧配色は暗いスレート屋根、灰色の石、落ち着いた漆喰、茶色の木材である。

- 形状の土台：[generate_kingdom_buildings.py](../../Tools/Blender/generate_kingdom_buildings.py) の `box`、`cylinder`、`mesh`、`extrude`、`beam`、`make_asset`
- 旧石材・屋根・窓：[generate_realistic_fantasy_buildings.py](../../Tools/Blender/generate_realistic_fantasy_buildings.py) の `surface`、`setup_materials`、`roof`、`lancet`、`door`
- 生活小物・露店：[generate_fantasy_town_props.py](../../Tools/Blender/generate_fantasy_town_props.py)
- 生産施設の部品：[generate_kingdom_support_buildings.py](../../Tools/Blender/generate_kingdom_support_buildings.py)
- 独立化できる塔：[generate_fantasy_town_facilities.py](../../Tools/Blender/generate_fantasy_town_facilities.py) の `square_watchtower`
- 独立化できる噴水：[generate_fantasy_civic_facilities.py](../../Tools/Blender/generate_fantasy_civic_facilities.py) の `fountain`
- 武器・訓練人形：[generate_fantasy_schools.py](../../Tools/Blender/generate_fantasy_schools.py)
- 旧材質の画像化：[export_block.py](../../Tools/Blender/UnityTownBlock/export_block.py) の `combined_mesh`、`bake`

この方式を使えば、新セットと同じ用途・モデル名を持ち、形と材質が旧セットに馴染む追加モデルを作れる。新モデルのメッシュをそのまま複製し、色だけ変える方法を前提としない。

## 建物5種類の作り方

| 対象 | 制作方針 | 必要な作業 |
| --- | --- | --- |
| 風車小屋 `Windmill` | 旧石材の塔体、帽子屋根、軸受、四枚の帆と横桟 | 専用の構造・輪郭を新設。羽根の回転域と本体の関係を確認 |
| 水車小屋 `Watermill` | 旧工房の梁・屋根・基礎、大きな水車、駆動軸、水路 | 水車・軸受・作業棟を接続する専用構成を新設 |
| 市場会館 `Market_Hall` | 旧倉庫・組合会館の材質、広い屋根、開放した柱廊、複数の搬入口 | 民家の変更版で済ませず、専用の平面と外観を作る |
| 見張り塔 `Watchtower` | 旧衛兵所にある石造塔を独立化 | 扉・敷居・窓の位置、上階への到達表現を調整。新作の木造塔と違う形でよい |
| 屋外便所 `Outhouse` | 旧木板・扉・片流れ屋根の小屋 | 換気口、扉、基礎を備える小型専用モデルを新設 |

作業の中心は風車・水車・市場会館の構造設計である。旧方式にこれらを作れない技術的制約は見つからなかったが、見た目の品質は個別の試作と確認が必要である。

## 露店・小物・橋など

8種類の露店は、旧露店の木枠・天幕・売り台を共通部品にし、商品を別々に作る。旧露店の青果や布を残したまま別の商品を足すのではなく、魚、パン、香辛料、花、肉、薬瓶、本、武器を見分けられる陳列に置き換える。

小物には既存部品を利用できるものが多い。荷馬車は旧荷車の車輪・軸・床板、袋の山は旧麻袋、巻いた布は旧布露店、薬草は旧診療所、訓練人形は旧戦士学校、噴水は旧広場、吊りランタンは旧酒場などを出発点にできる。

橋・桟橋・階段は旧石材・木材で新しく組む。ここは種類名を揃えるだけでは不十分で、両端の位置、通行幅、地面・水面・踊り場の高さを合わせる必要がある。

50モデルそれぞれの根拠・制作方針・作業規模は、[feasibility.json](../../Artifacts/CountryComparison/LegacyParity/feasibility.json) に記録した。「小・中・大」は相対的な作業規模であり、完成時間の見積もりではない。

## 実行確認

Blender 5.0.0の別プロセスで、調査用の木桶、見張り塔、噴水を旧関数から生成した。見張り塔は単独化に伴い扉・敷居を追加し、下段の窓を扉から離した。

各モデルで次を確認した。

- 旧方式のメッシュ生成と材質割り当て
- BaseColor・Normal・MetallicSmoothnessの512pxベイク
- 旧方式の軸設定によるFBX書き出しとBlenderへの再読込
- UVの保持、3枚の画像の存在、寸法差2mm未満
- 旧原本、既存の新旧Prefab、Countryシーン計236ファイルのハッシュが不変

これは制作経路の検証であり、50モデルの完成品質やUnityでの表示を保証する検査ではない。試作は `Artifacts/CountryComparison/LegacyParity/` にあり、ゲームの素材フォルダへの取り込みやCountryの再配置は行っていない。詳細は [probe_validation.json](../../Artifacts/CountryComparison/LegacyParity/probe_validation.json) を参照する。

## 制作前に必要な修正

旧生成スクリプトの多くと `KingdomCity/export_city.py`、`UnityTownBlock/export_block.py` の一括実行入口は、原本を `ArtSource/Blender/*.blend` として参照する。現在の実体は `ArtSource/Blender/Kingdom/*.blend` なので、保存先・読み込み先を明示的に直してから使う。今回の試作は呼び出す関数だけを利用し、出力先を調査用フォルダへ分離した。

旧Atlas方式は、Blenderのプロシージャル材質をそのままFBXへ渡すだけでは再現できない。ベイクした画像を、旧方式のURP/Lit設定へ割り当てる取り込み処理が必要である。王城用の既存取り込み処理は王城を対象にしているため、50モデル専用の追加Manifestと取り込み入口を用意するのが扱いやすい。

## 種類を揃えた比較への反映方針

1. 旧セットだけに50モデルを追加し、既存の旧91モデルを保持する。両国の基準を新セットの全141モデル名とする。学校のLv1〜5も対応させる。
2. 形・屋根・装飾・材質はそれぞれの方式で作り、役割、配置数、正面、接地、道路への接続基準を揃える。敷地は両方の外形を見て決め、片方を不自然に小さくしない。
3. 現在の `props[].old` にある別種類への代用を、同名モデルへの対応に置き換える。旧側の寸法参照にも追加50モデルの情報を登録する。
4. 未使用モデルも、役割に合う街区へ配置する。風車は風を遮らない一角、市場会館は市場、水車・橋・桟橋は連続した水路、屋外便所は裏庭、見張り塔は城壁へ置く。街の密度を保ちながら共通配置を組み直す。
5. 最後にPrefab名を基準として「旧側の不足0・旧側の未使用0・新側の未使用0」を検査し、新旧の画面で接地・入口・接続・貫通を確認する。
